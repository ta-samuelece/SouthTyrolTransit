# Data and realtime

* [Stop boards take live times from two sources](./live-times-two-sources.md) - where GTFS-RT has no prediction (often), boards, the map stop sheet and the widget overlay EFA delays matched by line and scheduled minute; trips do the same per stop, looking up the planner reference themselves when opened without one, which is the only way trains get live times (GTFS-RT carries buses only, and trains are never drawn on the map); GTFS-RT delays only propagate through updates with a stop_sequence.
* [Stop and line identifiers across GTFS, EFA and saved items](./identifiers-across-sources.md) - the station key (it:22021:468) is the only join between GTFS and EFA; saved stops and lines are keyed by derived keys, not GTFS primary keys, so changing stationKey, lineKey or TransportMode breaks saved items; the EFA liveRef string format couples the departure monitor to trip live times.
* [GTFS time, service days and the Europe/Rome rule in code](./gtfs-time-and-service-days.md) - GtfsTime.instant is the only correct way from a GTFS time and service date to an Instant; Departure.serviceDate has a default that is wrong past midnight; boards look back exactly one service day; two different "exceptions" maps.
* [The schedule and user databases](./schedule-database-lifecycle.md) - Importer changes reach existing installs only when GtfsImporter.VERSION is bumped; the schedule database has one migration (1 to 2, added columns) and the user database none; the importer writes raw SQL with hard-coded column lists; caches must key on ScheduleStore.version; queries go through ScheduleStore.withDatabase, which keeps a replaced database open until its users finish; how stop search is built.
* [How the timetable download and background sync really behave](./timetable-download-and-sync.md) - Periodic work registered at app start must carry the saved mobile-data choice (UPDATE replaces constraints); the one-off initial sync only runs without a timetable; conditional download only works for HTTPS from the same source; the timetable download uses its own client without a call timeout; unusable feeds are not retried; which failures count as offline; the TransitHttp retry contract.
* [STA's vehicle feed puts many buses on the run scheduled two hours earlier](./vehicle-feed-run-shift.md) - most city lines and some regional ones report, in GTFS-RT vehicle positions and trip updates, the trip_id of their line's run due at the vehicle's stop one UTC offset earlier; VehicleRunResolver moves each such vehicle, and its trip updates, to the run due there now before the snapshot is published.
* [Following a journey live](./follow-journey-live.md) - a started journey lives only in memory (ActiveJourney) and is lost when Android ends the app; a foreground service (location or specialUse type) runs FollowEngine, which applies matched runs' live times to the plan, computes the step and off-plan state in core/model, and feeds the screen and the notification; the planner's delays are re-fetched every 30 s through each leg's liveRef; the notification channel must be default importance to show on the lock screen, and a swiped-away notification is posted again because Android 14+ allows no non-dismissable one; the Android 16 Live Update needs POST_PROMOTED_NOTIFICATIONS.
* [Train numbers, bikes on board and distances along a run](./train-numbers-bikes-distances.md) - trip_short_name, bikes_allowed and shape_dist_traveled are imported (schedule database version 2) and shown on boards, the trip screen and journey legs only when the feed fills them; distances are taken as metres; "next stop in" and the progress bar need a fresh GPS fix; "travelling with a bike" filters results by the timetable runs the legs were matched to, not by the planner.
* [EV charging stations](./charging-stations.md) - three ODH requests (stations, charging points, their status) joined by the point's pcode; operators report a status only when it changes, so it counts as current for 7 days and is shown with its time, never as live; four status vocabularies including route220's undocumented 0/1; hydrogen and planned stations are dropped; code-like station names fall back to the address.
* [Bike boxes and e-bike sharing](./bike-boxes-and-ebike-sharing.md) - two mobility layers added 2026-10-25, each from two ODH requests joined by scode; Ecospazio's BIKE_CHARGER is e-bike sharing (bikes to rent, free docks), not charging for one's own bike; the bike box split by socket stays hidden because no site has a socket yet; out of service needs a current report; a full bike box site suggests the nearest one with space within 2 km.
* [Car park forecasts](./parking-forecasts.md) - the ODH parking forecasts count occupied spaces, not free ones; a value's time is the moment it predicts and its issue time is that minus the horizon; forecasts arrive hourly at :05, so the chart is hidden only after 90 minutes; loaded per car park when its sheet opens, with two hours of free history, cached five minutes; placeholder capacities and stopped feeds show no chart.
* [Live vehicles in the journey view](./journey-leg-live-vehicles.md) - journey-planner legs carry no trip id, so each transit leg is matched to a timetable run at its boarding station (line and minute, train fallback) and then treated like the trip screen; works only with a downloaded timetable and only until the vehicle leaves the boarding stop.
* [EFA parsing](./efa-parsing-quirks.md) - Which EFA fields count as realtime or cancelled, the different delay windows per parser, why trains are labelled "R", the empty-list-not-error contract, AddInfo filtering, and how the DOCTYPE guard works.
* [How service alerts are deduplicated, matched to departures and cached](./alerts-merge-and-matching.md) - GTFS-RT and EFA alerts merge on one identical normalised header plus overlapping periods, ignoring scope across sources; matching is string-exact and stop scope only counts for alerts without line scope; alerts count as live for 15 minutes.
* [Languages across sources](./languages-across-sources.md) - The app speaks en, de and it (Ladin was removed as a UI language on 2026-10-21; its feed texts still normalise to lld); never pass the comma-separated textLanguages() to EFA; localized() prefers a language-neutral text over fallbacks; the seven places a new UI language must be registered.

# App

* [Adding screens - routes, the Navigator, ViewModel keys and the search pattern](./app-screens-navigation-viewmodels.md) - how the first-run screens are gated before the app, how a route is declared and registered (screen<T> helper, Navigator method), how a tab is added, why parameterised ViewModels need an argument-derived key, the distinctUntilChanged search pattern from 8fcb0b7, and Hilt worker wiring.
* [App icons and the package name](./app-icons-and-package-name.md) - generate_icons.py (needs Pillow and numpy) only writes images; a new icon also needs a manifest activity-alias, an AppIcon entry and three strings; alias names are permanent; the package name is hard-coded in the icon switcher, the widget and MainActivity.
* [Backup and restore](./backup-and-restore.md) - Android Auto Backup carries user.db and the settings file, cloud only and only end-to-end encrypted (Android 9+); a restore marker from TransitBackupAgent triggers RestoreCleanup and re-applies the app icon on the next start; the user database and settings keys are now part of a restore contract; how to test with bmgr (never after a force-stop).
* [In-app updater internals](./in-app-updater-internals.md) - Hourly in-memory check throttle, the lenient certificate comparison, the three coupled updates/ paths, how version strings compare (build metadata and rc suffixes), and why the update dialog and the Settings section can disagree.
* [Map and design-system conventions](./map-and-design-system.md) - map content is one immutable value pushed layer by layer and marker ids must be unique across stops, vehicles and POIs; without a timetable the map's stops come from the EFA coordinate search; maps inside pages use ExpandableMapPage and enlarge where their small card sits; the one convention for showing progress along a run; the dark style falls back to the light override; four map types from one provider catalogue, Province rasters under the transit layers, credit per style and the font every style must serve; feed route colours are already used; the colour scheme (own palette by default, optional wallpaper colours and pure black) and the toggle group on surfaceContainer cards; the map's locate button is a FAB menu opened by a long press, with the layers button above it; reduced motion is read once.

# Build, test and release

* [There is no CI](./no-ci-every-check-is-local.md) - a GitHub Actions workflow existed for a few minutes on 2026-10-05 and was deleted; it built a debug APK with Java 17, ran no tests, and would have published debug-signed releases on every v* tag.
* [Test suite layout, and the network tests that are off by default](./test-suite-and-opt-in-live-tests.md) - Four kinds of tests across three modules; no screen or ViewModel is tested; the tests that download the real STA feed or hit the FTP server only run with -PliveTests=true or -PgtfsReal; TranslationsTest fails on any missing or stale en/de/it string.
* [Release build, R8 keep rules and build configuration](./release-build-r8-and-build-config.md) - R8 keeps only GTFS-RT protobuf and MapLibre explicitly and relies on library consumer rules for serialization, navigation, Room and Hilt, so only assembleRelease exercises it; the open-source licence list is generated by the AboutLibraries plugin and needs a resource keep rule and hand-maintained BSD notices; local.properties beats environment variables; no Kotlin Android plugin under AGP 9; Gson arrives transitively.
